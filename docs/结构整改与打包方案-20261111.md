## 1. 一句话结论

功能是健康的，问题&#x662F;**"单机定制"痕迹遍布**：3 个物理位置、2 个控制面、63 处硬编码路径、10+ 个计划任务互相抢。整改的核心不是搬家，而是**先引入一层路径间接（`SYNAPSE_HOME`）+ 一个审批闸门（policy），再谈打包**；否则打成 exe 也只是把"只能在你这台机器跑"封进一个安装包。

### 5.1 路径间接层（P1，必须最先做）

export const DATA = join(HOME, 'data');
export const CFG  = join(HOME, 'config');

### 5.2 审批中心（`packages\policy`）

所有写操作走唯一闸门：`allow / deny / ask`。

- **入口**：桥接 3100 的 `/api/send/*`、`/api/config/*`、`/api/persona/*`、`/api/role*`、`/api/pc-ops`；面板 3120 的全部 POST 与两个 GET 副作用端点；Hub 的启停与改配置。
- **复用现成能力**：桥接已有挂起队列（`/api/pending`，含 `approval` 与 `question` 两类）+ `APPROVE_WORDS`（`bridge.js:1723`）+ `questionTimeoutMs`，不必重写。
- **决策记录**：单表 `approval(id, at, actor, action, target, payload_hash, decision, decided_by, cost_ms)`，落 `audit.db`。
- **策略维度**：动作白/黑名单、目标白名单（`allow.private` / `allow.groups` 已有）、频率（`maxSendPerMinute/Hour` 已有）、时段、成本阈值（`cost-guard` 已有）。
- **默认值**：高危（改白名单、切人设、`pc-ops`、删图）默认 deny + 二次确认；发送类保留 60 秒撤回窗口。
- **面板加固**：3120 加 token（复用 `state\console-token` 机制），只读视图与写操作分离。

### 5.3 进程编排

Hub 成为唯一监督者，废除 4 条看守与全部自启计划任务，仅保留 1 条"登录启动 Hub"。  
子进程：`SnowLuma`（外部，只做探活与拉起尝试）→ `bridge` → `panel-server` → `qzone` → 扩展包。  
崩溃策略：指数退避重启，连续 5 次失败即停并在 Hub 中显示"需要人工处理"，不再无限拉起。

## 6. 打包方案

| 项              | 结论                                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 技术选型           | **Electron 33 + 自带 `node.exe`**（不用 pkg/SEA：`node:sqlite`、`@modelcontextprotocol/sdk`、`@snowluma/sdk` 组合会炸）             |
| 为何不用纯 Node 单文件 | 依赖全为纯 JS（无原生编译），但 `node:sqlite` 与动态 import 在 pkg 下不稳定                                                                  |
| 产物             | `SynapseHub-<ver>-x64.zip`（portable）+ `.exe` 安装器；预估 180–220 MB                                                         |
| 必需内置           | `runtime\node.exe`、`app\bridge`（含 node_modules 21 MB）、`app\panel-server`、`app\panel-ui\dist`、`app\qzone`、`app\presets` |
| 绝不内置           | DSH、SnowLuma、Live2D 模型、任何 `personas` 个人数据、任何 token                                                                     |
| 签名             | 首发无名（SmartScreen 会拦），文档需明示"更多信息 → 仍要运行"；后续补 OV 证书                                                                      |
| 端口             | 1918 DSH / 3000·3001·5099 SnowLuma / 3100 bridge / 3120 面板 / 3130 视频通话 / 3140+ 扩展，全部绑 `127.0.0.1`                      |

## 7. 零基础门槛与 A → B 路线

| 坎        | 现实                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------- |
| DSH      | 必装（246 MB + DeepSeek 账号登录）；桥接是为其 Cookie-auth / slash-RPC / remote.mux 协议定制的，**版本敏感**（`setup-dsh.mjs` 里 0.1.5→0.1.7 的机制差异就是证据） |
| SnowLuma | 必装 + 扫码登录；第三方网关，账号有风控风险                                                                                                       |
| 额度       | 需要 DeepSeek 侧可用额度                                                                                                             |

**A 方案（本次交付目标）**  
Hub 内置引导：检测 Node（已内置跳过）→ 检测 DSH 安装与运行 → 检测 SnowLuma → 自动执行 `setup-dsh.mjs --profile desktop`（**注意现脚本默认 `web`，本机实际跑 `desktop`，必须显式传参**）→ 引导扫码 → 自动发现 SnowLuma token（`snowluma-conn.js` 已支持 `discoverSnowLumaConnection`）→ 选人设 → 写 `config\secrets`。  
通过条件：用户会装两个软件 + 会扫码。

**B 方案（A 上线后迭代）**  
Hub 代管 DSH：下载官方安装包/便携版 → 解压到 `app\ext\dsh` → 用 `--user-data-dir` 隔离 → 拉起并展示登录窗口 → 自动重跑 `ensure-dsh-baseurl.mjs`。  
通过条件：用户只需扫码。

**为 C 留口**：`packages\llm-adapter` 先定义 `prompt() / events() / approve()` 三个方法，DSH 实现沿用现状；未来接 OpenAI 兼容端点时可替换，不改 `bridge.js` 调用面。

## 8. 扩展市场设计

### 8.1 为什么用 GitHub

- 无需自建服务；索引走 `raw.githubusercontent.com`，包体走 Release assets。
- **网络现实**：本机 `qq-bridge` 的 remote 已在用 `https://gh-proxy.com/https://github.com/...`，说明直连不稳；市场**必须**内置可切换镜像（直连 / gh-proxy / 用户自填）。

### 8.2 清单格式

索引仓 `synapse3-extensions`（公开）根目录 `index.json`：

```json
{
  "schema": 1,
  "packages": [{
    "id": "video-call", "name": "视频通话", "version": "0.1.0",
    "type": "service", "minCore": "3.33.0",
    "desc": "Live2D 视频通话（需 ASR + TTS）",
    "assets": { "url": "…/releases/download/v0.1.0/video-call-0.1.0.zip", "sha256": "…", "size": 1234567 },
    "ports": [3130], "dataDir": "video-call", "permissions": ["net.local"]
  }]
}
```

扩展包内 `ext.manifest.json` 声明 `type`（`service` / `window`）、`entry`、`ports`、`permissions`、`requires`。

### 8.3 安装与安全

1. 拉索引（缓存 24 h）→ 展示 → 用户点安装。
2. 下载 zip → **校验 sha256** → 解压到 `app\ext\<id>\<version>`（不允许覆盖运行中版本）。
3. **权限声明制**：默认禁止读 `config\secrets`、禁止写其他扩展目录；`service` 型只分配 3140+ 端口。
4. 首次启用弹风险确认（第三方可执行代码）。
5. 本地安装：支持拖入 zip / 输 Git URL（开发模式，打红标）。
6. 卸载：停进程 → 删目录 → 保留 `data\<id>`（询问）。

**首批扩展**：`desktop-pet`（`window` 型，Live2D 透明窗）、`video-call`（`service` 型 :3130）、`imagegen`（`service` 型，需用户自填 Ark Key）。
