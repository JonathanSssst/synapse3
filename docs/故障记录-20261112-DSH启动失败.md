# 故障记录：DSH 无法启动（2026-11-12 12:31）

> 结论先说：**是我造成的**。P2 阶段用 PowerShell 改写 `cordis.patch.yml`，把 UTF-8 无 BOM 的中文注释按 GBK 解码后重写成带 BOM 的文件，DSH 启动时 YAML 解析失败。已修复并加了防护。

## 1. 现象

DSH 弹窗「应用无法启动或已意外停止」，错误摘要指向 `cordis.patch.yml` 第 47 行附近：

```text
46 | # 螫?scripts/setup-dsh.mjs 编辑...
47 |    - id: mcp-snowluma
   --------^
```

## 2. 根因

P2 里改 MCP 路径用的是：

```powershell
$t = Get-Content $cfg -Raw
$t = $t -replace '...\qq-bridge', 'E:\Synapse\apps\bridge'
Set-Content -Path $cfg -Value $t -Encoding utf8 -NoNewline
```

三个问题叠加：

| 问题 | 后果 |
| --- | --- |
| `Get-Content -Raw` 未指定编码 | PS 5.1 对**无 BOM 文件按系统 ANSI（GBK）解码**，中文全变乱码 |
| `-Encoding utf8` | PS 5.1 写的是 **UTF-8 with BOM**（`EF BB BF`） |
| `-replace` + `-NoNewline` | 换行处理不一致，实际还吃掉了 `- id: ui-settings-account` 整块和一处 `- insert:` |

对比实测：

```text
备份文件 3711B  BOM=无  UTF-8=ok   结构行 20
损坏文件 3530B  BOM=有  UTF-8=ok   结构行 19（少一条 insert）
```

## 3. 修复

从 12 分钟前的备份 `cordis.patch.yml.bak-20261112` 恢复，再用新脚本按 UTF-8 精确替换：

```bash
node scripts/patch-dsh-profile.mjs \
  --file ~/.dsh/profiles/desktop/cordis.patch.yml \
  --restore ~/.dsh/profiles/desktop/cordis.patch.yml.bak-20261112 \
  --from 'E:\Users\...\default-workspace\qq-bridge' \
  --to   'E:\Synapse\apps\bridge'
```

脚本做的事：严格 UTF-8 读写、不写 BOM、保留原换行风格、只替换目标路径、**写入前比对结构行**（`- id:` / `- insert:` 序列必须完全一致，否则拒绝写盘）、原子替换。

修复后校验：

```text
路径替换 4 处 · 结构行 20 条未变 · 无 BOM · YAML 解析通过
14 个配置块齐全：ui-settings-account / ui-chat / ui-settings / mcp-mcbot /
agent-default-model / mcp-snowluma / mcp-snowluma-host / mcp-web-search-safe /
mcp-pcops / qq-mode / dsh-ops-file / dsh-ops-shell / mcp-minecraft / whale-pet
4 个被引用的 MCP 脚本在 E:\Synapse\apps\bridge\src 下均存在
```

损坏样本存证：`E:\BOT\archive\dsh-profile-20261112\`。

## 4. 顺带修掉的两个隐患

### 4.1 插件链接仍指向旧树

`~/.dsh/plugins/qq-agent-presets`、`~/.dsh/plugins/qq-mode-console` 两条 junction 原本指向 `...\qq-bridge\plugins\*`，而桥接已经在新仓跑——DSH 会用旧代码。已切到 `E:\Synapse\apps\bridge\plugins\*`。

用 `[System.IO.Directory]::Delete($p,$false)` 删链接，**不能用 `Remove-Item -Recurse`**：PS 5.1 那个组合会顺着 junction 删掉源目录内容。

### 4.2 提示词里的 `<主人QQ>` 占位符

早先"去个人信息"时把 `private:3681901185` 换成了 `private:<主人QQ>`，但这句是**给模型看的指令**，留着尖括号等于教模型编一个不存在的会话 key。已改为自然措辞「只在主人私聊里可用」——会话 key 本来就由桥接每轮下发，提示词不需要这个数字。

## 5. 防护

| 措施 | 位置 |
| --- | --- |
| 禁止用 PowerShell 改 UTF-8 文本；统一走脚本 | `scripts/patch-dsh-profile.mjs`（含 `--check` 模式） |
| 边界守卫新增 BOM 检测 | `scripts/check-boundaries.mjs`，CI 强制 |
| 清掉仓库里遗留的 1 个 BOM 文件 | `dsh/agent-presets/qq-chat/preset.yml` |

BOM 检测实测（临时造一个带 BOM 的文件并 stage）：

```text
apps/bridge/.bom-test.yml
  L1  [文件带 UTF-8 BOM]  BOM
[boundaries] 共 1 处命中  → exit=1
```

## 6. 一条通用教训

**"改了配置"和"配置能用"是两件事。** 这次我改完只看了一眼 `Select-String` 的计数（4 处替换成功），没做解析验证，结果让用户撞上了启动失败。以后改任何配置文件，收尾必须是「用加载它的那个解析器解析一遍」，而不是「grep 到就算成功」。
