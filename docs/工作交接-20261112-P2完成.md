## 2. 过程中发现的两个真问题

### 2.1 五条 `start-panel.bat` 轮询循环同时在跑

迁移时杀掉旧面板，**3 秒后它又回来了**（PID 变了）。继续查父链，发现 5 个 cmd 进程各自跑着 `start-panel.bat` 的 15 秒轮询：

```
[14088] [28460] [24316] [34040] [35404]  :: cmd /c E:\BOT\panel\start-panel.bat
```

这就是 11-07 审计里"4 条看守互相抢"的实际形态——不是 4 条，是 5 条。杀掉全部后才释放 3120。

**教训**：只停进程不管用，必须停掉"拉进程的那一层"。`PanelWatch`/`FireflyPanel` 计划任务已禁用，但**已在运行的 cmd 循环不会因为禁用任务而退出**。

### 2.2 健康检查的"假成功"

第一次启动新面板后，`/api/health` 返回 200，但 `db.path` 仍是 `E:\BOT\audit\audit.db`、node 版本是 v24——**那不是我起的实例，是旧面板**。我的实例因 `EADDRINUSE` 已退出。

若只看状态码，就会误判"迁移成功"。**判据必须是内容字段**（db.path / ui.dist / pid），不是 200。
