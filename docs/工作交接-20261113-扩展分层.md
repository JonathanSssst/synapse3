# 扩展分层：裸机只留三件事

2026-11-13。把 91 个工具按「裸机自带」和「装上才有」拆开，并做出扩展市场。

## 为什么要拆

原来桥接把 91 个工具一次性全注册给模型。**每个工具的描述和参数 schema，模型每次请求都要收一遍**——这是按 token 计费的。用户可能只用它聊天，却一直在为 B 站、抖音、读书、生图、空间这几十个工具的说明书付钱。工具越多还越容易误调。

所以划一条线：

| 类别 | 数量 | 内容 |
|---|---|---|
| **核心**（永远在线） | 55 | 读消息与上下文、发消息（文字/分条/图片/表情/语音/戳/文件/撤回）、表情包与语音素材、人设与记忆、主动唤醒 |
| **扩展**（装了才有） | 36 | B 站 8、抖音 3、空间 10、联网搜索 3、电脑助手 1、读书 2、语料 2、参考图 2、睡眠 1、日记 1、吃喝 1、刷视频 1、生图 1 |

判定原则：**「收发消息」的每一种形态都算核心**（语音和表情包只是消息的载体，不是独立能力）；**「人设」包含记忆**（砍掉记忆，人设就没有连续性，每次对话都像失忆）。其余一律扩展。

## 机制

注册期过滤，不是调用期。

`packages/extensions/index.mjs` 是唯一真源：`CORE_TOOLS`（白名单）+ `PACKAGES`（13 个内置扩展，各自声明包了哪些工具）。

`mcp-snowluma-safe.js` 包装了 `server.tool`，注册前问一句 `ext.toolEnabled(name)`：
- 在核心白名单 → 注册
- 属于某扩展 → 看装了没
- **未归属 → 不注册**（宁可少一个工具，也不要悄悄多烧 token）

这比调用期 403 强在哪：不注册，模型**根本看不到**这个工具，既不烧 schema token，也不会去调它然后拿到一堆拒绝。

原来那套 `socialV2.tools` 单工具开关保留，两道闸门取交集——用户在配置里单独关过的工具，装了扩展也不会回来。

## 迁移：不能让人升级完就掉功能

机器上如果已经在跑机器人，`config` 里一堆东西在用它，突然把 B 站、空间、抖音全关掉，用户会以为坏了。

所以 `bootstrap()` 分两条路：

| 情况 | 判据 | 行为 |
|---|---|---|
| 老用户升级 | DSH profile 里已经挂着 `mcp-snowluma` | **全部 13 个标记为已装**，保持现状；想精简自己去扩展页卸 |
| 全新安装 | 没有 `mcp-snowluma`（还没配过 DSH） | 只认领已配的 MCP 条目，其余不装——真正的裸机 |

实测：老用户路径认领 13 个，新装路径 0 个。

## 扩展市场

`packages/extensions/market.mjs`。这是整个程序唯一「把外部代码放到本机并让它跑起来」的入口，所以校验全是硬性的，任何一条不过就拒绝，不留半成品：

1. 只接受 https，host 必须在白名单（`raw.githubusercontent.com` / `github.com` / `gh-proxy.com` 等）；**重定向的每一跳都重新校验**，否则 https 跳一次就能绕过
2. sha256 必须与索引一致
3. 解压后逐条检查路径不越界（zip slip）、不许符号链接
4. `manifest.id` 必须与请求的 id 一致（防 A 的包冒充 B）
5. 文件数 ≤ 4000、解压后 ≤ 256MB（防 zip bomb）

实测拦截：`http://evil.com` → 「只允许 https」；`https://evil.com` → 「下载来源不在白名单」；缺 sha256 → 「拒绝安装，无法校验完整性」。

内置扩展不走下载，装 = 写一条状态记录（代码随程序发）；远端扩展卸载时连目录一起删。

## DSH 侧

`setup-dsh.mjs` 的 MCP 条目改为按安装状态生成：

- 核心必挂：`mcp-snowluma`、`mcp-snowluma-host`
- 装了电脑助手才挂 `mcp-pcops`；装了联网搜索才挂 `mcp-web-search-safe`
- 远端扩展读它自己的 `manifest.json.mcpServers`，脚本路径在 `data/extensions/<id>/`

**所有权账本**：状态文件里有 `knownMcpIds`，只增不减。没有它，卸载扩展后 DSH 里那条旧条目没人认领，会永远挂着一个连不上的 server。有这个账本才能既删干净、又不碰用户自己配的 MCP。

实测：装 pc → `mcp-pcops` 出现；卸 pc → 消失；用户自己的 `mcp-user-own` 全程保留。

新增 `--sync-mcp-only`：装个扩展只重写 MCP 区块，不重跑 preset / bundle / `dsh plugin install`。在控制台点一个开关，不该等半分钟，也不该动一堆无关配置。

## 控制台

侧栏新增「扩展」页：卡片显示名称、说明、包含哪些工具、装没装，一键装卸。底部显示当前操作的 DSH profile 和「装完要重启一次 DSH」。

装/卸后自动重启桥接（工具清单是它启动时注册的），失败会带上原因——桥接受外部实例占用时重启会拒绝，这是预期内的。

## 遗留

- **远端扩展的代码签名没做**。现在只校验 sha256，包本身不带签名。索引仓被攻破 + 同时改掉 sha256 就拦不住。要防这个得引入签名密钥，比这次的范围大。
- **扩展包没有版本升级流程**。装了 v0.1 想升 v0.2，现在是卸了重装，不做原地升级。
- **扩展市场索引目前是空的**（`synapse3-extensions` 仓 `packages: []`），界面能正常显示「连不上」或「没有可用的扩展」，不会崩。
- **内置扩展的代码没有真正分包**。B 站、抖音这些工具还写在 `mcp-snowluma-safe.js` 里，只是注册时被过滤掉。要达到「不装就不占体积」得把代码拆到独立 MCP server，那是更大的重构。
