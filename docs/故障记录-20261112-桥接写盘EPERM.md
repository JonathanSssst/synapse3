# 故障记录：桥接写盘 EPERM（2026-11-12 13:20）

> 一句话：**迁移脚本复制文件时把 Windows 安全描述符一起复制过去，目标文件拿到空 DACL（谁都不可写）**。桥接启动后写状态文件全部失败，连"唤醒投递"都发不出去。

## 1. 现象

桥接日志反复出现（路径被脱敏成 `***`）：

```
保存 socialV2 状态失败: EPERM: operation not permitted, rename '***' -> '***'
token 账本：写入失败 EPERM: operation not permitted, open '***'
[reserved2] 唤醒投递失败 private:<主人>: EPERM: operation not permitted, rename '***' -> '***'
```

同时 `dshReady` / `snowluma.connected` 都可能正常，容易误判成"网络问题"。实际上是本地写盘全废。

## 2. 排查路径与三个错误假设

| 假设 | 验证 | 结论 |
| --- | --- | --- |
| 沙箱限制（命令在受限环境跑） | 去沙箱重启，报错依旧 | ❌ 不是 |
| 文件被其他进程占用 | 停掉桥接后仍不可写 | ❌ 不是 |
| ACL 被继承破坏 | `Get-Acl` 显示**规则数 0** | ✅ 命中 |

决定性证据：

```text
迁移来的文件：icacls 无任何 ACE，Get-Acl 规则数 0
新建的文件  ：BUILTIN\Administrators:(I)(F) / SYSTEM / Administrator 三条
```

空 DACL 的含义是**没有任何主体拥有权限**——连所有者都读不了。之所以命令行里 `cat` 还能读到，是因为提权进程带 `SeBackupPrivilege`，绕过了 ACL 检查。

## 3. 根因

`scripts/migrate-to-v2.mjs` 原来用：

```js
fs.copyFileSync(src, dst);
```

Windows 上它走 `CopyFileEx`，**会连同安全描述符一起复制**。跨卷复制且进程没有 `SeSecurityPrivilege` 时，目标文件得到的是一个空 DACL。

受影响范围：`data/state/bridge/` 下 **61 个文件**（桥接要写的全部状态文件），其余文件只读，暂时看不出问题。

## 4. 修复

**单个文件**的正确做法是"读出内容 → 新建文件 → 替换"，让新文件按父目录**继承**正常 ACL：

```bash
cat "$f" > "$f.new" && rm -f "$f" && mv "$f.new" "$f"
```

**注意 `cp` 不行**：GNU cp 在 msys 环境下同样会复制 ACL，等于把空 DACL 又抄一遍。这一点实测踩过——第一轮用 `cp` 重建，61 个文件仍然不可写。

**排查/验证**用与业务进程同权限的 Node 试开，而不是用提权 shell：

```js
try { const fd = fs.openSync(p, 'r+'); fs.closeSync(fd); } catch (e) { /* e.code === 'EPERM' */ }
```

提权 shell 能写不代表桥接能写——这是本次最大的干扰项。

修复后：

```text
剩余不可写文件：0
EPERM 日志：0 条
dshReady: true | snowluma.connected: true | accountOnline: true
```

## 5. 已落进代码的防护

1. `migrate-to-v2.mjs` 的复制改为 `fs.writeFileSync(dst, fs.readFileSync(src))`，并在结尾加**权限自检**：扫 `data/` 与 `config/`，有不可写文件直接打印出来。
2. 迁移脚本注释写明为什么不能用 `copyFileSync`，避免以后"优化"回去。

## 6. 顺带解决：DSH 端口漂移

DSH 桌面版每次启动随机分配 API 端口，配置里写死的 `1918` 是历史值（那其实是本机反向代理，上游已断）。DSH 重启后桥接日志表现为"连上事件流但收到 0 帧"，还提示"多半是协议/版本不兼容"，很容易走错方向。

新增 `scripts/detect-dsh.mjs`：按 DSH 独有的响应指纹 `dsh web authentication required` 扫描回环端口定位 API。

```bash
node scripts/detect-dsh.mjs          # 只打印
node scripts/detect-dsh.mjs --apply  # 写回 config/bridge.json
```

实测从 55 个监听端口中唯一命中正确端口（误报的 Vite 预览端口已通过"弱特征只做兜底"排除）。

## 7. 教训

- **跨卷复制文件不要用 `copyFileSync`**，Windows 上它连 ACL 一起搬。
- **验证权限要用业务进程的身份**，提权 shell 的"能写"毫无参考价值。
- 日志里的 `EPERM ... '***'` 是脱敏后的样子，别拿它猜路径——直接扫目录更有效。
