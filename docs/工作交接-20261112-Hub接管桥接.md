# 工作交接 · Hub 接管桥接（2026-11-12）

## 目标

桥接（3100）和面板（3120）一直是「外部实例」：早期会话用 bash 直接
`node src/bridge.js` / `node apps/panel-server/server.mjs` 起的，不在 Hub 的
`children` 里。后果是配置向导保存后 `restart` 会拒绝，改了配置也不生效。

切换后由 Hub 统一编排：启动时自动拉起，重启、停止、状态都由控制台管。

## 切换前确认没有看守链

```
46540  node src/bridge.js        ← 父 46500 = WorkBuddy 的一次性 bash
10872  node apps/panel-server/…  ← 父 16632 = 同上
```

两个父进程都是一次性 shell（不是轮询脚本），杀掉 node 后 shell 自己会退出，
不会像早先 `start-panel.bat` 那样把服务再拉起来。`cmd.exe` 里也没有任何
匹配 bridge/panel 的残留看守。

`bridge.lock` 存的是旧 PID，强杀后会残留，切换前删掉（新桥接会自己重建）。

## 三个根因（按发现顺序）

### 1. 载荷里根本没有桥接的第三方依赖

换成 Hub 启动后，桥接立刻 `exit 1`：

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'js-yaml'
  imported from ...\resources\app\bridge\src\bridge.js
```

`apps/bridge/node_modules` 是**符号链接**，指向旧树
`E:\Users\Administrator\Documents\deepseek-harness\default-workspace\qq-bridge\node_modules`。
源码运行时靠这个链接蒙混过关，但 `build-hub.mjs` 不带 `--with-deps` 时压根没复制
依赖，打包出来的 exe 从来没能独立跑起桥接 —— 之前一直是外部实例在撑着，
所以没暴露。

修 `scripts/build-hub.mjs`：

- 依赖复制改为**默认行为**，用 `cp()` 的 `dereference: true` 跟随符号链接，
  把真实文件（31MB / 97 个包）复制进载荷，顺带解除对旧树的依赖。
- 不再默认跑 `npm ci`（离线也能构建，且不会破坏源目录那个链接）；
  只有源目录都没有 `node_modules` 且显式给了 `--with-deps` 才安装。
- 第 8 节加**依赖自检**：逐个核对 `package.json` 里声明的 7 个生产依赖，
  缺一个就让构建失败，而不是等用户装完 exe 启动才发现。

载荷体积 86.9 → 108.3 MB，exe 102.7 → 105.2 MB。

### 2. Hub 只在 `--autostart` 时拉服务

`main.cjs` 原来把 `sup.startAutos()` 包在 `if (START_HIDDEN && sup)` 里，
手动双击 exe 后托盘亮着但服务不上线。改成每次启动都拉起（已有端口在监听的
一律跳过，不抢）。

服务页也补了两个信息：`refresh()` 会标记「端口 X 由外部进程占用（Hub 未托管）」，
前端把 `detail` 显示出来 —— 有没有接管成功，一眼能看出来。

### 3. 重启竞态：旧进程的 exit 把新进程的记录删了

第一次验证 `restart('bridge')` 时出现矛盾结果：

```
restart → { ok: true, pid: 14704 }
3100    → LISTENING 14704        （新进程确实起来了）
services → bridge: up, pid: null, error: "exit 1"
```

`stop()` 同步删 `children`，`start()` 立刻写入新记录；但旧进程的 `exit` 事件是
异步的，晚到一步就执行了 `this.children.delete(id)`，把新进程的记录一起删掉。
结果「端口在、进程在，界面却显示未托管」，下一次 restart 又会被端口判据拒绝。

修法：`exit` 回调先核对归属，不是当前记录的那个 child 就直接 return。
