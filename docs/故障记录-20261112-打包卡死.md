# 故障记录 · 打包卡在 packaging（2026-11-12）

## 症状

`npm run build`（electron-builder portable）跑到这一步就不动了：

```
• packaging  platform=win32 arch=x64 electron=33.4.11 appOutDir=...\win-unpacked
• no custom electronDist provided, unpacking default Electron distribution
```

十分钟没有任何输出，`win-unpacked` 目录也不生成文件。偶尔会以
`Timeout awaiting 'request' for 600000ms` 结束。

## 根因（三层，逐层踩）

### 1. Electron 分发包在龟速下载

盯着 `%TEMP%\electron-download-*\electron-v33.4.11-win32-x64.zip` 的大小变化：

```
22:07  848,123 字节
22:08  896,396 字节     ← 8 秒涨了 48KB，约 4.8 KB/s
```

包里 110MB，按这个速度要几个小时，表现就是"卡住"。而本地缓存
`%LOCALAPPDATA%\electron\Cache\503bc58...\electron-v33.4.11-win32-x64.zip`
里明明已经有一份完整的，@electron/get 却不认（缓存 key 跟 URL 绑定）。

实测国内镜像 6 MB/s，差三个数量级：

```
https://npmmirror.com/mirrors/electron/33.4.11/electron-v33.4.11-win32-x64.zip
```

### 2. 镜像覆盖地址会拼出 404

设 `ELECTRON_BUILDER_BINARIES_DOWNLOAD_OVERRIDE_URL` 后报：

```
⨯ Response code 404 (Not Found) for
  https://cdn.npmmirror.com/binaries/electron-builder-binaries/nsis-3.0.4.1.7z
```

镜像的目录布局是 `<name>/<version>/<file>`，而官方 release 是
`<repo>/releases/download/<release>/<file>`。覆盖 URL 只拼了文件名，
少了 release 目录这一层。**这个变量别用**，它还会让本来能命中的
`%LOCALAPPDATA%\electron-builder\Cache\downloads\<hash>\` 全部失效。

### 3. 输出目录已存在时触发批量删除拦截

换方案后报了新错：

```
⨯ [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]
  {"count":65,"threshold":50,"scope":"turn","targets":["...\win-unpacked\locales"]}
```

electron-builder 每次构建都会先清空 `win-unpacked`，`locales` 有 65 个文件，
超过环境 safe-delete 钩子的 50 个阈值。

## 能跑通的命令

```bash
cd apps/hub
./node_modules/.bin/electron-builder --win portable --x64 \
  -c.electronDist=E:/Synapse/apps/hub/node_modules/electron/dist \
  -c.directories.output=E:/Synapse/dist/hub2
```

三个要点：

1. **`-c.electronDist`** 指向 `node_modules/electron/dist`（npm install 时就解压好的完整分发目录），
   跳过下载与解压，这是绕开第 1 层的关键。
2. **不设任何镜像覆盖变量**，让 nsis / 7zip / nsis-resources 走默认 URL —— 这样能命中已有缓存。
3. **`-c.directories.output` 换一个新目录**，全新构建，不触发批量删除。

总耗时约 4 分钟（其中 7z 压缩占了 3 分多，中间产物
`synapse-hub-0.1.0-x64.nsis.7z` 82MB）。

产物：`dist/hub2/SynapseHub-0.1.0-x64.exe`（102.7 MB，版本信息与图标正常）。

## 附带发现

- **portable 冷启动要 30~40 秒**：exe 每次运行都把 350MB 解压到
  `%TEMP%\<随机串>\`，然后才拉起真正的进程。这是 portable 形态的固有代价，
  托盘常驻之后只有重启电脑才会遇到，暂时接受。
- 某次窗口显示后约 2 秒自己隐藏了，加了 `close` 事件追踪后复现不出来
  （连续两次后再没出现，进程号各不相同）。留了追踪行，以后再遇到直接看
  `%TEMP%\synapse-hub-trace.log` 里有没有 `close 事件触发`。
- 本机磁盘紧张（E: 96% / C: 97%，`%TEMP%` 里 DSH 的工作区快照占 8.4GB），
  构建时容易误判成"空间不足"。实际这几轮失败都不是空间问题。
