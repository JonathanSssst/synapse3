# 工作交接 · 首启向导（2026-11-12）

## 为什么做

原来的「体检」页只会说「缺什么」，改不了任何东西。`checkConfig` 明明标了
`fix: 'edit-config'`，前端却压根没实现这个动作 —— 点不了。结果是：这套配置只在
我这台机器上存在，换台电脑拿到 exe 的人根本配不起来。

## 做了什么

侧栏的「体检」改成「配置」，页面上是三步表单，下面折叠着原来的环境体检。

| 步骤 | 填什么 | 为什么是这几项 |
| --- | --- | --- |
| 第 1 步 · 你是谁 | 主人 QQ、允许私聊的号、允许的群 | 这是唯一"必须人填"的信息，其它都有合理默认 |
| 第 2 步 · QQ 网关 | SnowLuma 目录、HTTP/WS 地址、访问令牌 | 目录决定能不能帮你重启网关；端口默认 3000/3001 |
| 第 3 步 · 智能体 | DSH 地址（可自动探测）、令牌 | 端口每次启动都变，所以给了「自动探测」按钮 |

几个刻意的设计：

- **字段定义、校验规则只在服务端写一份**（`firstrun.cjs` 的 `GROUPS`）。前端只负责
  把 spec 画成表单、把值原样交回去。校验错的 key 直接对应 input 的 `data-key`。
- **写回哪个文件取决于现状**。桥接的 `configPath()` 是「config/bridge.json 优先，
  回落 ROOT/config.json」。向导如果无脑往 v2 位置写，会凭空多出一份配置把旧的盖掉，
  旧配置里没进表单的字段（pricing / slang / socialV2 …）就全丢了。所以找到当前生效
  的那个文件，改它。
- **从模板起底，但只覆盖表单里的字段**。全新安装时读
  `config/default/bridge.example.json`（脱敏过的完整配置，25 个顶层字段），
  用户填完只改那 8 个值，其余原样保留。
- **主人 QQ 填了、私聊白名单留空时自动补上**。`allow.private` 为空 +
  `allowAllWhenEmpty=false` 会让机器人连主人的消息都拒掉，这是最容易踩的坑。
- **原子写**：先写同目录临时文件再 rename。桥接随时可能读这个文件，直接覆盖会有
  一瞬间读到半截 JSON 的窗口。
- **改之前先备份**到 `backups/config/bridge-<时间戳>.json`；什么都没改就不写盘。
- **首次启动直接进配置页**（`needsSetup`），不让人对着空白服务列表发懵。

## 顺手修的两个 bug

1. `checkSnowluma` 只读环境变量 `SNOWLUMA_HOME`，不读配置里的 `snowluma.homeDir`。
   正常安装的用户不会去设环境变量，于是体检里永远显示「未设置」。
2. `services.detectDsh()` 用 `process.execPath` 跑探测脚本 —— 源码模式下那是
   `electron.exe`，只因为环境里恰好有 `ELECTRON_RUN_AS_NODE=1` 才像 node；
   打包后 `process.execPath` 是 `SynapseHub.exe`，直接失效。而且脚本路径
   `__dirname/../../scripts` 在 asar 里已经出了 resources。
   现在改用 `runtimeNode()`，脚本路径给三个候选，打包时由 `extraResources`
   放进 `resources/runtime/detect-dsh.mjs`。

## 遗留

- **ACL 收紧没做**。`config/default/README.md` 的硬规则要求"复制成实例后立即收紧
  ACL"，但 Windows 上 `icacls /inheritance:r` 一旦 grant 失败，用户可能把自己锁在
  配置文件外面 —— 对零基础用户风险大于收益。等有把握了再加。
- **桥接不是本程序托管时，保存后无法自动生效**。向导会提示"请手动重启一次"。
  等 Hub 全面接管托管之后这条会自然消失。
- 安装版（nsis）未验证，`config-default` 与 `detect-dsh.mjs` 在安装版里走的是同一套
  `resourcesPath`，理论上一致，但要真的装一次才算数。
