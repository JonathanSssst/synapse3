# 自主时间：把「自己动」收进一个扩展

2026-11-13。扩展不再各自定时，所有自主行为统一由 `activity-time` 调度。

## 问题

上一版刚把能力拆成「核心 + 扩展」，但自主性还散着：

- 桥接里有五个独立定时器：刷 B 站、自由时间、上网、休息提醒、早安晚安
- 每个都写死了一段「现在该干什么」的提示语，比如「用 qq_bili_hot 看热门…」
- **扩展装没装，它们都照跑**。没装 B 站时它照样会被提醒去刷 B 站
- QQ 空间还有自己的常驻进程，循环判断「今天要不要发说说」

结果就是「扩展只提供能力、不自作主张」这条原则，在实现上是假的。

## 现在的分工

```
扩展                 只声明：这件事叫什么、什么时段适合、一天几次
  ↓
activity-time        只决定：现在要不要开口
  ↓
模型                 自己决定：做不做、做什么、做多久
```

三层各管一段，谁都不越界。

- **扩展**：在注册表里加 `activities` 字段，说明能力本身，不写「什么时候该用」
- **activity-time**：汇总所有已装扩展的活动 + 自己的基础活动（早安/晚安/自由时间/休息），按时间窗、冷却、日限额筛选，到点唤她一次
- **模型**：收到的是「现在有一段空档，这些事可以做」，不是任务清单

## 关键实现

### 桥接的总闸

`activitySchedulerExternal()` —— 默认返回 true，五个旧定时器全部直接 return。设 `cfg.socialV2.activityScheduler = 'legacy'` 可以回退（排查对比用）。

**没有动核心唤醒**：有人找你、潜水超时、回复检查、概率唤醒照旧。那是「她想起你」，属于人设，不属于扩展活动。

### 端点

`POST /api/activity/wake`

```json
{ "activityId": "bili-browse", "label": "刷会儿 B 站", "hint": "...", "key": "private:xxx" }
```

只做两件事：把 `activityCandidate` 写进会话状态，然后 `scheduleWakeV2(key, 'activity:<id>')`。

`activity` 在唤醒优先级表里是最低的（10）——有人发消息永远排在她想找点事做前面。同时加进了 `TIMER_WAKE_REASONS`，否则会话繁忙被暂存后，会因为「未读已清空」而被静默丢掉。

如果她正在睡（`wakeConfig.sleepUntil` 未到），端点返回 409，不打扰。

### 提示语

`buildWakePromptV2` 里新增 `activity:` 分支，只说：

> 这不是别人找你，是日程里的一段空档。做什么、做多久、或者干脆不做，都你自己决定。
> 想看看还有哪些可选，调 qq_activity_now；做了或决定不做，都用 qq_activity_done 记一笔。

**不指定做什么**，这是和旧实现最大的区别。

### 三个工具

| 工具 | 作用 |
|---|---|
| `qq_activity_now` | 此刻适合做的 + 全部可选（含时段、日限额） |
| `qq_activity_done` | 记账。记了调度器就不再问同一件事 |
| `qq_activity_plan` | 查看/修改日程。主人说「以后别刷抖音了」时用它 |

### 记账与防打扰

- 日限额按**提议次数**算，不是按执行次数。否则她每次都拒绝时会被一天问十几次——那不叫自由，叫骚扰
- 提议后 15 分钟内没记账，不再提新的事
- 两次提议至少隔 45 分钟（`minGapMin`）
- 安静时段 `00:30-07:30` 绝对静默

### QQ 空间

常驻进程（`qzone-bot.mjs` 的循环）从服务表里移除了。发不发、什么时候发，改成她在 `qzone-post` 活动里自己决定，一天最多提议一次。

## 活动清单

基础（activity-time 自带，不依赖任何扩展）：早安 07:30-09:30、晚安 22:30-23:59、自由时间 10:00-22:00（每天 2 次）、休息提醒 23:00-01:00。

扩展声明的：

| 扩展 | 活动 | 时段 | 每天 |
|---|---|---|---|
| B 站 | 刷会儿 B 站 | 19:00-23:30 | 2 |
| 抖音 | 刷会儿抖音 | 19:30-23:30 | 1 |
| QQ 空间 | 发条说说 / 翻动态 | 10:00-23:00 / 12:00-23:00 | 1 / 2 |
| 联网搜索 | 上网逛逛 | 09:00-22:30 | 2 |
| 读书 | 读会儿书 | 20:00-23:30 | 2 |
| 刷视频 | 连着刷视频 | 20:00-23:30 | 1 |
| 语料库 | 学几个新词 | 20:00-23:00 | 1 |
| 参考图 | 看看参考图 | 15:00-22:00 | 1 |
| 吃喝 | 吃点东西 | 07:00-22:00 | 3 |
| 生图 | 画张图 | 10:00-23:00 | 1（标了 costly） |

**电脑助手（pc）不声明任何活动**。让 AI 自主操作电脑是这次分层里唯一明确禁止的事——它只能在被要求时动手，且每次都要审批。

**睡眠计划也不声明活动**，它是约束条件：睡着时整个调度器静默。

## 验证

| 项 | 结果 |
|---|---|
| 活动表 | 装 activity-time + B 站 → 5 个活动（4 基础 + 1 扩展） |
| 时段筛选 | 08:00 早安 / 12:00 自由时间 / 21:00 自由时间+B站 / 01:00 无（安静时段）/ 03:00 无 |
| 工具注册 | 不装 activity-time：91 个（跳过 3）；装了 + B 站：66 个（55 核心 + 11 扩展） |
| 服务表 | 装了才托管调度器；没装时服务表里没有它 |
| 迁移 | 已装过扩展的机器自动补装 activity-time，不会升级后突然不动 |

## 遗留

- **调度器是独立进程，和桥接之间没有心跳**。桥接挂了它还在跑，提议会失败（401/404），只是打日志，不会自己重试。
- **`config/activity-time.json` 没有 UI**。现在只能让 bot 自己改（`qq_activity_plan`），或者手改文件。
- **旧定时器代码没删**，只是被总闸挡住。留着是为了 `activityScheduler === 'legacy'` 能回退，稳定后再清。
- **活动时长没有上限**。她能连续刷两小时 B 站——目前只限制「提议频率」，不限制「单次做多久」。
