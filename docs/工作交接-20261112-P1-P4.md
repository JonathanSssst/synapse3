## 2. P1：路径间接层

### 2.1 新增 `packages/paths`

全仓唯一路径真源。关键设计是**代码根与数据根分离**：

- 代码根（`apps/`）跟着程序走；
- 数据根（`HOME`）跟着用户/安装盘走。

这个区分是踩出来的：第一版把两者混在一起，用 `SYNAPSE_HOME=E:\BOT` 验证时，面板去 `E:\BOT\apps\panel-ui\dist` 找前端——不存在。修正后 `ui.dist` 正确指向 `E:\Synapse\apps\panel-ui\dist`。

支持两种布局并存，靠存在性探测而不是开关：

```
v2（迁移后）    <HOME>/data/state        <HOME>/data/db/audit.db   <HOME>/data/personas
legacy（迁移前）<HOME>/state             <HOME>/audit/audit.db      <BRIDGE>/personas
```

这就是 P2 能"改数据不改代码"的原因。

## 3. P3：SynapseHub

### 3.1 结构

```
apps/hub/
├─ main.cjs            主进程：IPC、单实例、退出时停子进程
├─ preload.cjs         只暴露白名单 API，渲染层拿不到 Node
├─ services.cjs        编排：托管/外部服务、探测、退避重启、needsHuman
├─ bridge-console.cjs  控制台客户端：x-console-token、pending、answer
├─ firstrun.cjs        体检：Node/DSH/SnowLuma/配置/人设/前端
├─ renderer/           原生 HTML+CSS+JS，无构建步骤（降低打包风险）
└─ electron-builder.yml
```

### 3.2 编排规则

- 外部服务（DSH:1918、SnowLuma:3000）**只探测、不代管**——第三方程序的生命周期归用户。
- 托管服务（bridge:3100、panel:3120、qzone 无端口）可起停；无端口服务用 **pid 文件 + `process.kill(pid,0)`** 探活（`tasklist` 在中文系统输出 GBK，解析不可靠，已弃用）。
- 崩溃退避：2s→4s→8s→16s→30s，**连续 5 次进 needsHuman 并停止自动重启**。旧版 4 条看守无限互拉，正是 `EADDRINUSE` 的根因，这里从机制上封死。

### 3.3 审批中心

桥接原本只能"在 QQ 里回复通过/拒绝"，没有 HTTP 应答入口。本次在桥接里补了一个受控端点：

```js
POST /api/pending/answer   { key, text }
→ 调用既有的 handlePendingAnswer(p, text, key, true)
```

**没有复制判定逻辑**——通过/拒绝的词表、回执、挂起清理全部复用原函数，两边结果天然一致。鉴权沿用控制台的 `x-console-token`，POST 另受 Origin 校验保护。

只读验证（桥接在跑，未触发任何写操作）：

```text
GET /api/pending  → { pending: [] }
GET /api/status   → mode / dshReady / ownerQQ / allowGroups / snowluma …
```

## 4. P4：打包与发版

### 4.1 载荷分层

```
dist/hub-payload/
├─ app/         bridge · panel-server · panel-ui/dist · qzone
├─ packages/    paths · policy · llm-adapter     ← 必须在安装根
├─ runtime/     node.exe（83 MB）
└─ extensions/
```

`packages/` 之所以在安装根而不是 `app/` 内：`app/bridge/src` 的 `../../../packages` 要能解析到。目录层级是与源码树一一对应的，换布局会立刻在 `node --check` 之后的首启暴露。

实测：`node scripts/build-hub.mjs --allow-missing-ui` → 载荷 86.5 MB，入口语法检查通过，组装布局下路径解析正确（`BRIDGE=…/hub-payload/app/bridge`）。

### 4.2 流水线

`.github/workflows/release.yml`（tag `v*` 触发）：
扫描 → 单测 → 构建前端 → 构建 Hub → 组装载荷（含 bridge 生产依赖与内置 node）→ electron-builder portable → SHA256 → draft Release。

Release 正文已写明三条安装前提与 SmartScreen 说明。
