# 工作交接 · 开机自启（2026-11-12）

## 为什么做

上一轮把「点 X 关闭」改成了缩到托盘、服务继续在后台跑。但那只解决了一半：
电脑重启之后控制台不会自己回来，用户还得去翻 exe 双击一次，
等于托盘常驻的价值丢了一半。

## 做了什么

1. **侧栏开关** `开机自启（后台）`：勾上写系统登录项（`HKCU\...\Run`），取消就删。
   读回来的状态以注册表为准，不是「调用没报错」就算成功。
2. **`--autostart` 启动模式**：注册表里写的是 `<exe> --autostart`。
   带这个参数启动时窗口 `show: false`，只挂托盘图标。
   例外：托盘创建失败时必须开窗，否则用户完全没有入口。
3. **自启时补拉服务**：只挂托盘而服务没起来，用户会以为机器人还活着。
   `--autostart` 会走 `Supervisor.startAutos()` 把 bridge 和 panel 拉起来。
   先 `refresh()` 再判断，已经在监听端口的一律跳过，不会撞端口。
   qzone 不在自启范围 —— 它是定时发说说的，不该每次开机就自动往外发内容。

## portable 版的坑

exe 每次运行都会解压到临时目录，`process.execPath` 指向的是那份副本。
把它写进注册表，第二天重启就失效了。electron-builder 为此注入
`PORTABLE_EXECUTABLE_FILE`，指向用户双击的那个真实 exe —— 自启路径优先取它。

## 怎么手动关

托盘右键 → 退出并停止服务，重开控制台后取消勾选；
或直接删注册表
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `SynapseHub` 值。

## 遗留

- 安装版（nsis）尚未打包验证：它的自启路径走 `process.execPath`，
  需要真的装一次才能确认。
- 源码版的自启值名是 `electron.app.Electron`（Electron 默认名），
  与打包版的 `SynapseHub` 不是同一个值，两者互不覆盖。
  开发时别把源码版的自启项留在机器上。
